# 配車デモ LP — UIバランス改善案

対象: `http://localhost:5180/lp`  
前提: 文案改善は別ファイル [`lp-text-extract.md`](./lp-text-extract.md) で進める。本書はレイアウト・視認性・情報の重さの改善案。  
読者: 中堅企業の管理職・経営者（ITリテラシー低め、判断を急かされない）

---

## 1. いまのバランスの問題（スクリーンショットから）

| 症状 | 原因 | 読者への影響 |
|---|---|---|
| 左が薄く、右だけ重い | 2カラムで左=短文、右=図+操作UI | 「説明は左、作業は右」と誤解。LPなのに操作画面に見える |
| 同じ内容が3回出る | 左本文・図キャプション・図下noteが重複 | 長く感じる。どれが正本か分からない |
| 図が「370px幅のデモUI」のまま | 体験デモ用 `.stage` をそのまま埋め込み | スマホ画面をPCの半分に置いたように見え、安っぽい |
| 見出しと本文のサイズ差が大きい | H2 が大きく、本文16px・行間1.75 | 見出しだけ目に入り、本文が流し読みされる |
| セクション間の余白が均一で長い | 各 band が 40–48px padding | スクロールが長く、途中で離脱しやすい |
| FAQが入力欄に見える | 白枠+質問文のみ（閉じた状態） | クリックできるのか、未入力なのか分からない |
| ナビが小さく詰まっている | 13px・4リンク+CTAが1行 | タップしづらい。何のページか分からない |
| ヒーローが中央寄せで浮いている | 左寄せ本文に対し、上だけ独立 | 「デモの続き」感が弱い |
| 変わらない/変わるの2箱が地味 | 本文の下に小さく2列 | 経営層が最も知りたい対比が埋もれる |

---

## 2. 改善の方針（3原則）

1. **左=結論、右=証拠** — 左に「1文で言うと何か」、右は図だけ（操作ボタンは最小化）
2. **1セクション1メッセージ** — 図キャプションとnoteの重複を削る。どちらか一方に統一
3. **デモUIと説明UIを分ける** — LP内の図は「読む図」。戻る/次へは小さく、または自動再生

---

## 3. セクション別の改善案

### 3-1. ヘッダー

**現状**  
配車のデモ | いまの現場 さっきの画面 … 画面に戻る

**改善案**

```
[配車のデモ]                    [画面に戻る（塗りボタン）]
説明ページ — デモのあとに読む
────────────────────────────────────────
[いまの現場] [さっきの画面] [人が増えたとき] [心配]
```

- 1行目: ブランド + 唯一の強いCTA（画面に戻る）
- 2行目: 「説明ページ — デモのあとに読む」（ページの役割を固定）
- 3行目: アンカーナビ（タップ領域 44px 以上、下線で現在地）

**CSS目安**  
- ナビリンク: 14px → 15px、padding 8px 12px  
- sticky のまま、背景は不透明 `#fafaf8`（透けない）

---

### 3-2. ヒーロー

**現状の問題**  
- 見出しが長い1文  
- ボタン2つが同列で、どちらが主か弱い  

**改善案**

| 要素 | 変更 |
|---|---|
| 幅 | 全幅960px、**1カラム**（2カラムにしない） |
| 見出し | 最大2行。28–32px。**太字は1フレーズだけ**（例:「載せるかは人が決める」） |
| 本文 | 2文まで。16px、行間1.6 |
| ボタン | 主=「画面に戻る」1つ。副=「下へ」はテキストリンク |
| 余白 | 下 padding 32px（次セクションとの間を詰める） |

**ビジュアル**  
ヒーロー下に細い区切り線 + 「ここから3つの話です（現場→変化→人数）」の1行ガイド。

---

### 3-3. 2カラムセクション（現場 / 変化 / 人数）

**現状の問題**  
右の図カードが高さ400px超、左は200px程度 → **右に視線が固定され左がスキップされる**。

**改善案A（推奨）: 上説明・下図**

```
[ラベル]
[見出し H2]
[本文 3–4文]
[変わらない | 変わる]  ← 該当セクションのみ
────────────────────
[図（幅100%、max 720px 中央）]
[図は自動で3段／8段を切替。操作は「前へ」「次へ」の小リンクのみ]
```

- スマホでも縦の流れが自然
- 左の空白問題が消える

**改善案B: 2カラムを維持する場合**

| 左 | 右 |
|---|---|
| width 55% | width 45% |
| 見出し+本文+対比表 | 図のみ（キャプションは図内に1行） |
| `align-items: start` | 図の `max-height: 420px` + 内部スクロール禁止 |

**図カードのスタイル変更**

- `.lp-figure` から `.stage` の margin 12px を除去 → padding 16px 統一
- 図内の **大きな黒ボタン（荷物を降ろす等）を LP では非表示** または `font-size: 12px` のリンク化
- `1 / 8` は図の右上バッジ（小さく）
- キャプション（cap-above）は **図の上ではなく左本文に統合** → 図下 note は削除

---

### 3-4. 「変わらない / 変わる」対比

**現状**  
本文の下に小さな2箱。経営層向けの核心が弱い。

**改善案**

```
┌─────────────────┬─────────────────┐
│ 変わらない       │ 変わる           │
│ ✓ 地域の担当     │ → 同じ表を見る   │
│ ✓ 載せる判断     │ → 空車に候補     │
│ ✓ 休息・FAX確認  │ → 確認は人が見る │
└─────────────────┴─────────────────┘
```

- 背景: 左 `#f3f3ee`、右 `#fff` + 左ボーダー 3px `#1a1a18`
- セクション3（さっきの画面）**だけ**に置く。他セクションには置かない
- 見出しレベル: H3、14px ラベル + 16px 項目

---

### 3-5. FAQ

**現状**  
白い横長ボックスが5つ。閉じていると「未回答フォーム」に見える。

**改善案**

- `<details>` の summary 左に **「＋」アイコン**（開くと「−」）
- 1項目開いたとき、他は閉じる（任意）
- 最大幅 640px（本文より狭く → 読みやすい行長）
- 背景 band を白、各 item は `#f3f3ee` 背景 + 枠なし

**並び順**（不安の強い順）

1. 勝手に配車しないか  
2. 今すぐ導入か  
3. 地域分けを変えるか  
4. FAX・電話  
5. 休息チェック  

---

### 3-6. 持ち帰り3点 + フッター

**現状**  
3カードは良いが、FAQの直後で疲れる。最後のCTAが左寄せで弱い。

**改善案**

- 3カード: アイコン不要。**数字 1 2 3** を左上に大きく（24px、薄いグレー）
- フッター: 薄いダーク帯（`#1a1a18`、padding 32px）
  - 白文字で見出し1行
  - 白ボタン「画面を見る」
  - 注記は 12px、opacity 0.7

---

## 4. タイポグラフィ・余白（数値）

| トークン | 現状 | 提案 |
|---|---|---|
| `--lp-max` | 1080px | **960px**（図と本文の行長を揃える） |
| H1 | clamp 22–32px | **24–28px**（大きすぎない） |
| H2 | clamp 22–28px | **20–24px** |
| 本文 | 16px / 1.75 | **17px / 1.65**（管理職向けに少し大きく） |
| ラベル（kicker） | 12px 茶 | **13px グレー `#5c5c56`**（装飾色をやめる） |
| セクション padding | 40–48px | **32px**（上下）。band 間は 0、背景色で区切る |
| 図と本文の gap | 28–40px | **24px**（1カラム時） |

---

## 5. 配色

**現状**  
白 → 薄ベージュ → 白 の交互。差が弱く、セクション境界が分かりにくい。

**提案**

| セクション | 背景 |
|---|---|
| ヒーロー | `#fafaf8` |
| いまの現場 | `#ffffff` |
| さっきの画面 | `#f3f3ee` |
| 人が増えたとき | `#ffffff` |
| FAQ | `#f3f3ee` |
| 持ち帰り | `#ffffff` |
| フッターCTA | `#1a1a18` |

- グラデーション背景は使わない（信頼感優先）
- アクセント色（茶 `#8a4a22`）は **ラベルから撤去**

---

## 6. 図（StoryStage）のLP専用モード

実装時の分岐案: `StoryStage` に `variant="lp"` を追加。

| 体験デモ | LP埋め込み |
|---|---|
| 大きい黒ボタン | テキストリンク「次の段へ」 |
| cap-above フラッシュ | キャプションなし（左本文に統合済み） |
| note ボックス | 非表示 |
| 戻る | 非表示 or 小リンク |
| 自動 | 5秒ごとに次段（任意・停止ボタン付き） |

これで右カラムの「操作画面感」が消える。

---

## 7. 優先度（実装順）

| 優先 | 項目 | 効果 |
|---|---|---|
| P0 | 2カラム → **1カラム（上説明・下図）** | バランス問題の根本解消 |
| P0 | 図内の大ボタンをLP用に縮小/非表示 | 「デモの続き」誤解の解消 |
| P1 | キャプション重複削除（左本文に一本化） | 読了時間短縮 |
| P1 | 変わらない/変わる を目立つ対比表に | 経営層向けの芯 |
| P2 | FAQ の開閉UI改善 | 不安解消の読みやすさ |
| P2 | ヘッダー2段化 + CTA強調 | 迷子防止 |
| P3 | 図の自動再生 | 操作不要の説明体験 |
