# 運送 配車ナレッジ — テーマ別要件定義書

## 背景

依頼がネット・FAX・電話に分かれ、配車は担当者ごとの勘で組まれている。空で戻る車と、隣の担当が持つ帰り荷がつながらない。過去の単価・条件は頭の中か紙に残り、次の案件へ渡せない。

## 課題

- 入口がバラバラで、同じ形の一覧にならない
- 配車マンの熟練と勘がデータになっていない
- 「今回の配車の場合は…」を過去条件から示せない

## 対象ユーザー

- Primary: 配車担当（操作する）
- Secondary: 運行管理者・経営（見る・判断する）

## デモの目的

1. 依頼が同じ一覧に並ぶことを見せる
2. 空で戻る車に、隣の荷物が候補として出ることを体験する
3. 載せる／載せないは人が決める、と手で分かる

## Must（v1）

- 入口（所要約8分・今日見る2点）
- 第1部 問題の図（8段・次へのみ）
- 配車盤で帰り荷候補を「載せる／載せない」
- 第3部 同じ図の再演（3段）
- 休息下限9時間の確認表示
- 仮ナレッジは JSON（DBなし）
- `npm run build` 成功

## Should

- 要確認の FAX 1件を人が直して未処理から落とす
- 依頼詳細・遊技機案件の閲覧画面
- 「この画面の意図」折りたたみ
- `/board` 単独表示

## Won't

- DB 連携
- 実 OCR
- 自動運賃確定・自動配車
- ai-demo-core / Trial / ROI
- 車両マスタ管理画面
- 第1部のインタラクティブ化

## 成功条件

- 図解のあと、盤で候補を載せる／載せないがどちらもできる
- 載せても休息の確認は消えない
- 金額・配車の確定をシステムが言わない
- 説明文を開かなくても盤の操作は完走できる
